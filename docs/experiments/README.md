# Experiment Records

Use three connected layers for long-term continuity:

| Layer | Purpose | Update point |
|---|---|---|
| `../project_state.md` | Current baseline, confirmed conclusions, open questions and exact next action | Each meaningful result or decision |
| Dated records in this directory | Conditions, actions, measurements, evidence paths and interpretations | During experiments |
| `../reports/` | Concise weekly and sprint summaries for review | Session or reporting-period close |

Start a continuation by reading the state and the active experiment record. Keep earlier experiment results; append new evidence or clearly label a correction instead of silently overwriting history. A report is not a substitute for the detailed experiment record.

For each test, retain the design/testbench, model/corner/temperature, supplies, dimensions, stimulus, analysis settings, measurement definition, result and next action. Mark unverified settings explicitly. Separate numerical measurements from screenshot estimates and hypotheses. Retain code versions and CSV paths when available; do not invent missing exports.

## Images

The user manually archives important images in OneNote. Record a useful caption and the original Temp path. When preparing a report or recalling a result, read the Temp image if it still exists. If it is missing or unreadable, request that specific image from the user. Do not claim direct OneNote access or fabricate the missing visual. Existing archived Week 6 assets remain available; no automatic bulk image-copy workflow is required.

## Closing a session

Update the state, experiments and applicable report with actual results. List unresolved mentor feedback and the next verification step. Keep weekly and sprint summaries separate, preserve templates, and remind the user about both when both are due. Week 7 has both deliverables.
